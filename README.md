# MiniFeed

**MiniFeed** — учебный проект по распределённым вычислениям: общая лента текстовых постов с комментариями, лайками и просмотрами. Цель — на практике показать распределение данных по узлам, две копии постов и комментариев, обработку отказа узла хранения и надёжную асинхронную доставку событий статистики.

## Возможности по техническому решению

- Регистрация и вход по имени пользователя и паролю.
- Создание и просмотр текстовых постов и комментариев.
- Общая лента по 20 постов с кнопкой «Загрузить ещё».
- Постановка и снятие лайка, учёт просмотров.
- Хранение каждой публикации и её комментариев на двух из трёх узлов.
- Восстановление недостающих копий после отказа узла.
- Асинхронное обновление статистики через RabbitMQ с обработкой повторной доставки.

В проекте **не предусмотрены** изображения, редактирование и удаление постов, подписки, рекомендации и поиск.

## Планируемая архитектура

- **Client:** простой веб-интерфейс на HTML/CSS/JavaScript.
- **API Gateway:** HTTP API, регистрация, авторизация, приём событий в outbox.
- **Feed Service:** лента, распределение постов и комментариев, репликация и восстановление.
- **Storage Node × 3:** независимые узлы с локальными базами данных.
- **RabbitMQ:** очередь событий лайков и просмотров.
- **Stats Service:** подсчёт просмотров, хранение состояния лайков, дедупликация событий.

Планируемый стек: **Python, FastAPI, SQLite, RabbitMQ, Docker Compose и pytest**. Его окончательный выбор согласуется командой до начала реализации.

Полное описание компонентов, гарантий и проверок находится в [техническом решении](docs/tr.md).

## Структура репозитория

- `.github/` — настройки и шаблоны GitHub.

## Разработка

1. Создайте рабочую ветку от актуального `main`.
2. Вносите код и документацию в рабочей ветке.
3. При изменении архитектуры обновляйте `docs/tr.md`.
4. Создайте Pull Request в `main`, опишите изменения и назначьте ревью.
5. После замечаний исправьте их в той же ветке; объединяйте изменения только после согласования.

## Запуск и тестирование

Реализация находится в разработке. Команды запуска через Docker Compose и команды тестирования будут добавлены, когда появятся исполняемые сервисы. Текущий документ описывает **планируемое поведение**, а не готовую к запуску систему.
